🚨 MALICIOUS SITE - CORS VULNERABILITY DEMO 🚨

WARNING: This is a demonstration of a CORS vulnerability attack. In a real scenario, this would be a malicious website trying to steal user data.

CORS Attack Simulation

This site will attempt to access the protected user details from localhost:3003 by exploiting the CORS misconfiguration.

Attack Steps:

  1. User logs into the vulnerable app (localhost:3003) and gets a session cookie
  2. User visits this malicious site while still logged in
  3. This site makes a request with credentials: 'include'
  4. Browser automatically sends the session cookie with the request
  5. Due to CORS misconfiguration, the server accepts the cross-origin request
  6. Sensitive user data is stolen and displayed below

🔑 Key Point: The attacker doesn't need to steal the session token - the browser automatically sends cookies when credentials: 'include' is used!

How to Fix This Vulnerability:

  • Fix CORS Configuration: Set specific allowed origins instead of reflecting the Origin header
  • Use Access-Control-Allow-Origin: https://yourdomain.com (specific domain)
  • Never use: Access-Control-Allow-Origin: * with Access-Control-Allow-Credentials: true
  • Cookie Security: Set cookies with SameSite=Strict or SameSite=Lax
  • Additional Protection: Implement proper CSRF tokens
  • Best Practice: Use httpOnly cookies and avoid storing sensitive tokens in localStorage

✅ Secure CORS Configuration Example:

// Instead of this vulnerable code:
res.setHeader("Access-Control-Allow-Origin", req.headers.origin);
res.setHeader("Access-Control-Allow-Credentials", "true");

// Use this secure code:
const allowedOrigins = ['https://yourdomain.com'];
if (allowedOrigins.includes(req.headers.origin)) {
  res.setHeader("Access-Control-Allow-Origin", req.headers.origin);
  res.setHeader("Access-Control-Allow-Credentials", "true");
}
